# Demo

This page explains how to run a **complete end-to-end demo** of the MultiDiseasePred pipeline using the provided notebook.

The demo covers the following stages:

- data loading
- feature preprocessing and alignment
- model training
- model checkpoint selection
- external validation
- probability calibration
- final performance evaluation

All steps are implemented in the notebook:

MultiDiseasePred_Train_Validation.ipynb

---

# 1. Launch the Notebook

First start Jupyter:

```bash
jupyter notebook
```

Then open the notebook:  

MultiDiseasePred_Train_Validation.ipynb  

Run the cells **sequentially from top to bottom**.

---

# 2. Configure Dataset Paths

Before running the pipeline, update the dataset paths defined in the configuration section of the notebook.  

Example configuration:  

```python
UMN_TRAIN_CSV = "data/umn/train.csv"
UMN_TEST_CSV  = "data/umn/test.csv"

MIMIC_CSV     = "data/master_dataset.csv"
STANFORD_CSV  = "data/stanford/stanford_features_labels.csv"
```

Replace these paths with the locations of your local datasets.  

---

# 3. Configure Output Paths

All artifacts generated by the pipeline will be saved under the configured output directory.  

Example configuration:  

```python
OUTPUT_DIR = "output/"

MODEL_CKPT_PATH     = OUTPUT_DIR + "best_multidiseasepred.pt"
FEATURE_SCALER_PATH = OUTPUT_DIR + "feature_scaler_umn.pkl"
CALIBRATOR_PATH     = OUTPUT_DIR + "calibrator_isotonic.pkl"
```

These files store:  

- the trained model checkpoint  

- the feature preprocessing scaler  

- the calibration model

---

# 4. Run the Training Pipeline

The training stage performs the following steps:  

1. Load the training dataset  

2. Align feature columns with the expected training schema  

3. Apply preprocessing and feature scaling  

4. Construct PyTorch dataloaders  

5. Train the MultiDiseasePred model  

6. Monitor validation performance  

7. Save the best model checkpoint  

After training, the following artifacts are generated:  

```bash
output/
├── best_multidiseasepred.pt
├── feature_scaler_umn.pkl
```
These artifacts are required for evaluation and external validation.  

# 5. Run External Validation

The notebook supports evaluation on external datasets such as MIMIC or other hospital cohorts.  

The external validation workflow includes:  

1. Load the external dataset  

2. Align feature columns with the training feature schema  

3. Apply the saved feature scaler  

4. Generate prediction logits using the trained model  

5. Fit a task-wise calibration model  

6. Convert logits to calibrated probabilities  

7. Compute performance metrics

---

# 6. Probability Calibration

Calibration is performed using isotonic regression.  

The calibration step uses:  

- prediction logits generated by the model  

- corresponding ground-truth labels  

The calibrator learns a monotonic mapping from model scores to calibrated probabilities.  

If calibration cannot be fitted for a task (for example when only one class is present), the pipeline falls back to the raw sigmoid probabilities.  

---

# 7. Evaluation Metrics

The pipeline reports several performance metrics for each prediction task.  

Typical metrics include:  

- AUROC (Area Under the ROC Curve)  

- AUPRC (Area Under the Precision-Recall Curve)  

- normalized PRC  

- sensitivity  

- specificity  

- bootstrap confidence intervals  

Example output format:

```bash
Task 00 (outcome_hospitalization)
AUROC = 0.85
AUPRC = 0.60
Sensitivity = 0.79
Specificity = 0.76
```

# 9. Tips for Running the Demo

To ensure successful execution:  

- verify dataset paths before running the notebook  

- ensure feature columns match the training schema  

- run cells sequentially without skipping steps  

- reuse the saved scaler for all evaluation datasets  

- ensure calibration uses the same score scale as model outputs

```bash
dataset preparation

feature preprocessing
        ↓
model training
        ↓
checkpoint selection
        ↓
external dataset loading
        ↓
```

Following this workflow allows users to reproduce the full MultiDiseasePred modeling pipeline on their own datasets.
